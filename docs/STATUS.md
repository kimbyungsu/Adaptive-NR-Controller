## 1. 결론

**원래 구상의 기본 규칙은 내 폰에서 돌아가는 1차 버전까지 왔다. 나머지 절반은 아직 계획 단계다.** 나머지 절반은 여러 폰 지원, 폰 스스로 하는 자동 검사, 장소 학습, 배터리 효과 측정이다.

**된 것.** 5G가 붙었다 떨어졌다 하는 곳(지하철 등)에서 "잠깐 LTE로 쉬었다가 다시 5G를 시험"하는 판단과 실행.
- 폰에서 시험 명령으로 순서대로 눈으로 확인했다(09-28 새벽): LTE로 쉬기 → 5G 다시 시험 → 끄면 원래 설정으로 되돌리기.

**원래 대화보다 엄격해진 것.** 대화 뒤에 사용자가 정한 원칙이다.
- 5G 우선일 때만 작동한다.
- 설정 화면도 같이 바뀐다. → 09-28 밤 "설정 화면 = 사용자가 고른 고정값, 상단바 = 실제"로 바뀌었다(DESIGN §5.12).
- 작동 중에는 작은 점을 띄운다.
- 끝나면 사용자가 고른 원래 설정으로 돌아간다.

**아직 안 된 것.**
1. **(09-28 저녁 기준) 실제로 불안정한 곳에서 스스로 LTE로 내린 적이 아직 없다.** → 09-28 23:56에 처음 스스로 쉬었다(아래 09-29 결과).
   - 오늘 약 12시간 실사용하는 동안 기준을 넘은 상황이 없었다. 기준은 데이터를 쓰는 중 2분 안에 5G가 3번 끊기는 것이다.
   - 한 번 끊겨 "경계"로 간 적은 6번 있었고, 모두 5~10분 안에 "양호"로 돌아왔다.
   - 규칙이 틀린 것인지, 그런 장소에 가지 않은 것인지는 아직 가를 수 없다.
2. **내 폰 한 대에서만 확인했다.** 기기는 갤럭시 노트20 울트라, 순정 One UI 5다.
   - 다른 폰에서 켜면 "관찰만" 하거나 시작하지 않는다.
3. **재부팅하면 꺼진다.** PC를 연결해야 다시 켤 수 있다. → 09-29 밤: 앱으로 옮기면 재부팅 뒤 스스로 켜지는 길을 폰에서 확인했다(아래). 제품 앱은 아직 만들지 않았다.
4. **배터리를 실제로 얼마나 아끼는지 아직 재지 않았다.**

**09-29 결과.**
- **실제 불안정 구간에서 처음으로 스스로 작동했다.** 09-28 밤 약 3분 동안 5G가 8번 풀렸고, 그중 데이터를 쓰는 중 끊김이 85초 안에 3번이었다. 컨트롤러가 23:56에 LTE로 쉬었고, 5분 뒤 다시 시험해 통과했다(research §2.13).
- **새 방식의 전제가 폰에서 틀린 것으로 나왔다.** 쉬는 동안 설정 저장값은 5G 우선 그대로였는데, 설정 화면은 LTE 우선으로 보였다. 삼성 설정 화면이 저장값이 아니라 "사용자 허용 모드" 칸을 그대로 보여 주기 때문이다(삼성 코드로 확인).
  - 그래서 "설정 화면은 사용자가 고른 그대로, 쉬는 동안 실제만 LTE"를 이루려면 다른 방법이 필요하다. 사용자 칸은 그대로 두고 다른 칸(절전 등 다른 사유)으로 5G를 막는 방법이 유력하다.
- **절전 칸 방식 폰 실험(09-29 19:36~19:52, research §2.14).**
  - 원하던 모습이 됐다. 쉬는 동안 설정 화면은 5G 우선, 상단바는 LTE였고, 그때 LTE 우선을 누르자 컨트롤러가 즉시 알아챘다.
  - 대신 절전 칸 막힘은 재부팅 뒤에도 남았다. 쉬는 중 폰이 꺼졌다 켜지면 "설정은 5G 우선인데 실제는 LTE"로 남고, 설정 화면으로는 풀 수 없다. 안전장치가 필요하다. 방향은 사용자 결정 대기(§7).
- **재부팅 뒤에도 PC 없이 도는 길을 폰에서 확인했다(09-29 밤, research §2.15, DESIGN §5.13).**
  - 방법: 폰의 통신사 설정에 우리 앱의 서명 인증서를 시험용으로 덧붙여, 폰이 이 앱을 "통신사가 인정한 앱"으로 대하게 한다. SIM은 건드리지 않는다. PC가 설치 때 한 번만 한다.
  - 확인한 것: ① 앱이 그 자격을 얻었다. ② PC가 보낸 시험 명령을 받은 앱이 자기 자격으로 5G를 막았다가 풀었다(PC가 직접 바꾼 것이 아니다). ③ 폰을 껐다 켜도 자격이 남았고, 앱이 스스로 깨어났다. ⑤ 판단에 쓰는 재료(5G 연결, 통화 중 여부 등)를 앱에서도 받을 수 있다. 못 받는 두 가지는 다른 재료로 대신할 수 있다.
  - 확인 중인 것: ④ 앱이 몇 시간, 하룻밤 동안 꺼지지 않고 살아 있는지.
  - 한계: SIM 교체, 공장 초기화, 삼성 업데이트 등이 있으면 자격이 풀릴 수 있다. 그때는 PC로 다시 설치해야 한다("영구"가 아니라 "재부팅 후 유지").

**09-30 제품 앱 "5G 자동 제어"가 폰에서 돈다(research §2.17, DESIGN §5.13).**
- 무엇: 폰 앱 하나. 상단바 표시 대신 빠른 설정 타일 "5G 자동"(탭 = 자동 제어 켜기·끄기, 길게 = 앱 화면). 앱 알림을 꺼 두면 알림 창에 줄이 없다.
- 폰에서 확인: 쉬는 동안 **설정 화면은 5G 우선 그대로, 상단바는 LTE** → 2분 뒤 스스로 5G 재시험·통과. 쉬는 중 LTE 우선을 누르면 앱이 즉시 물러나고 자기 막음을 푼다. 쉬는 중 타일을 끄면 즉시 5G로 돌아온다. 예전 방식의 치명 결함(쉬는 중 LTE 누름을 놓침)이 풀렸다.
- 아직: 실제 불안정 구간 자동 쉬기, 쉬는 중 재부팅, 부팅 뒤 자동 시작(제품 앱), 장시간 생존, **앱 안 처음 설정(무선 디버깅)** — 지금은 개발 시험용으로 PC가 인정 목록에 한 줄을 넣어 두었다.

**09-28 밤 설계 변경(사용자 결정, DESIGN §5.12).** 사용자가 설정에서 고른 5G 우선/LTE 우선을 고정값으로 둔다.
- 컨트롤러는 설정 화면 값을 건드리지 않고, 실제 연결만 LTE로 쉬게 한다.
- (계획) 쉬는 동안 설정 화면은 5G 우선 그대로이고, 상단바는 LTE다. 점은 5G 우선인 동안 계속 뜬다. → 09-29 폰 확인: 설정 화면도 LTE로 보였다(위 09-29 결과).
- (계획) 쉬는 중 LTE 우선을 누르면 설정 값이 바뀌므로, 컨트롤러가 이를 보고 멈추도록 만들었다. → 09-29 폰 확인: 쉬는 중 화면이 이미 LTE로 보여, 그대로 누르면 폰이 아무것도 하지 않는다. 이 방식으로는 해결되지 않았다(위 09-29 결과).
- (09-28 밤 기준) 구현과 PC 시험은 끝났다. → 09-28 22:48 폰에 설치했고, 09-29 기기 확인에서 위 결과가 나왔다.
- 설치·사용 안내는 [INSTALL.md](INSTALL.md)에 새로 썼다. 지금 버전은 PC로 설치하는 개발용 시제품이다. 다른 사용자용 앱이 되려면 무엇이 필요한지도 적었다.

**오늘 저녁 폰 확인에서 새로 알게 된 것.**
- 쉬는 중 사용자가 설정에서 LTE 우선을 눌렀는데, 컨트롤러가 이를 놓치고 72초 뒤 5G 우선으로 덮어썼다. 사용자 원칙을 어긴 결함이다(§5 2번).
  - 화면이 예전 값을 보이던 경우는 폰이 알림을 보내므로 고쳤다(설치함).
  - 화면이 LTE로 맞게 보일 때 LTE를 다시 누르면 폰이 아무것도 하지 않아 **설정 화면으로는 고칠 수 없다.** 폰 알림의 "LTE로 계속" 버튼 같은 다른 수단이 필요하다.
- 설정 화면은 새로 열 때만 실제 값을 읽는다. 홈 버튼으로 나갔다 오면 예전 값을 보여 줄 수 있다(§5 11번).

**지금 말할 수 있는 것.** "내 폰에서 원래 구상대로 동작하는 규칙을 만들었다"까지다. "배터리를 아낀다"와 "여러 폰에서 된다"는 아직 말할 수 없다.

**자동 검사 5단계의 현재 모습.**
- 시작할 때 확인하는 것(하나라도 안 되면 관찰만 한다):
  - SIM이 1개인지
  - 삼성 설정 화면 칸이 있고 번호 짝이 맞는지
  - 상단바 자리가 비었는지
  - Wi-Fi 여부를 알 수 있는지(새 버전부터)
- 데이터 사용량을 읽을 수 있는지도 확인하지만, 못 읽으면 관찰만 하는 것이 아니다. 경고를 남기고 "큰 다운로드 중 미룸" 없이 제어한다.
- 대화의 3·4단계("LTE로 한 번 바꿨다 되돌려 보기")는 하지 않는다. 사용자 허락 없이 폰 설정을 바꾸지 않는다는 원칙 때문이다.
- 결과 보고서도 없다.

**대화의 기기 정보와 실제 기기가 다르다.** 대화에서 말한 사용자 기기는 ExtremeROM, Android 15였다(#103). 실제로 연결된 폰은 순정 One UI 5(Android 13, 펌웨어 N986NKSSAHYH1)다.

## 4. 쓰는 방법

1. 폰을 PC에 연결하고 USB 디버깅을 켠다(재부팅 뒤에는 매번 필요).
2. `python pc/nrctl.py start` — 컨트롤러가 켜진다. 케이블을 뽑아도 계속 돈다.
3. 평소처럼 쓴다. 폰 설정에서 **5G 우선**을 고르면 컨트롤러가 작동하고, **LTE 우선**을 고르면 손을 뗀다.
   - 작동 중에는 상단바 신호 옆에 작은 점이 뜬다.
   - 5G가 데이터를 쓰는 중에 자주 끊기면 실제 연결만 LTE로 쉰다. 상단바는 LTE로 바뀐다. 설정 화면도 LTE 우선으로 보인다(09-29 폰 확인: 삼성 화면이 실제 사용자 칸을 보여 줌 — 원하는 "5G 우선 그대로"는 다른 방법 필요). "자주"는 2분에 3번, 또는 데이터 서비스 끊김을 뜻한다.
   - 쉬기 시작하고 5분 뒤, 화면이 켜져 있으면 5G를 다시 시험한다. 실패가 거듭되면 기다리는 시간이 10·20·40분, 최대 60분으로 늘어난다.
   - Wi-Fi로 인터넷을 쓰는 동안에는 쉬고 점이 사라진다. LTE로 쉬게 해 둔 상태였다면 원래 설정으로 되돌린다(§5 1번).
   - 쉬는 중에는 설정 화면도 LTE 우선으로 보인다(삼성 화면이 실제 사용자 칸을 보여 줌, 09-29 확인). 이때 LTE 우선을 그대로 눌러도 폰이 아무것도 하지 않아 컨트롤러가 알아채지 못한다. LTE로 계속 쓰려면 5G 우선을 한 번 눌렀다가 LTE 우선을 누른다(값이 바뀌므로 알아챈다). 이 불편을 없애는 방법은 결정 대기(§7).
   - 설정 화면으로 지금 모드를 확인할 때는 뒤로 가기로 닫았다가 다시 연다. 홈 버튼으로 나갔다 오면 예전 값이 보일 수 있다(§5 11번).
4. 가끔 PC에 연결해 `python pc/nrctl.py pull` → `python pc/nrctl.py report`로 무엇을 했는지 본다.
5. 끄기: `python pc/nrctl.py stop`. LTE로 쉬게 해 둔 상태였다면 원래 모드로 되돌리고 꺼진다.

## 5. 알려진 결함과 한계

**고친 것**

1. **Wi-Fi에서도 점이 뜨던 결함.** 09-28 저녁에 사용자가 발견했다.
   - 원인: 점을 띄울 때 "설정이 5G 우선인가"만 보고, 인터넷이 Wi-Fi로 나가는지는 보지 않았다.
   - 고친 뒤의 동작(상황별):
     - 5G 우선인 채 카페 Wi-Fi에 붙음 → 점이 사라지고 컨트롤러가 쉰다. Wi-Fi를 끄고 나가면 점이 다시 뜨고 판단을 다시 시작한다. **폰에서 확인**(20:08 Wi-Fi 연결 → 점 사라짐, 20:09 Wi-Fi 끔 → 점 다시, 5G 우선 그대로).
     - 지하철에서 LTE로 쉬던 중 집에 와서 Wi-Fi에 붙음 → 사용자의 원래 설정(5G 우선)으로 되돌리고 점을 숨긴다. 🧪 폰에서는 아직 확인하지 못했다(시험 중 사용자가 Wi-Fi를 켜기 전에 쉬는 시간이 끝났다).
     - 원래 LTE 우선이던 사용자가 Wi-Fi에 붙었다 떨어지기를 반복함 → 컨트롤러는 아무것도 바꾸지 않는다. 5G로 바꾸는 일은 없다.
     - LTE로 쉬던 중 사용자가 설정에서 LTE 우선을 누르고 Wi-Fi에 붙음 → 아래 2번을 고친 버전부터 LTE를 따른다.
     - 통화 중에 Wi-Fi에 붙음 → 점은 바로 숨기고, 되돌리기는 통화가 끝나고 30초 뒤에 한다.
     - Wi-Fi에 붙어 있는 중에 전화가 옴 → 점은 계속 숨긴 채다.
     - 폰이 Wi-Fi 여부를 알려 주지 못하는 경우(감시를 못 붙임) → 컨트롤러는 관찰만 한다. 모르는 채 셀룰러로 가정하지 않는다.
     - PC 도구로 일시정지해 둔 중에 Wi-Fi에 붙음 → 되돌리지 않는다. 일시정지는 "바꾸지 말라"는 뜻이기 때문이다. 다시 켜면 그때 되돌린다.
   - 상태: 폰에 설치함(20:00). 점 숨김·복귀는 폰에서 확인했다. 쉬는 중 Wi-Fi 되돌리기는 🧪.

2. **쉬는 중 사용자가 LTE 우선을 눌러도 컨트롤러가 놓치고 5G로 덮어쓰던 결함.** 09-28 20:24 폰 시험에서 발견했다.
   - 있었던 일: 컨트롤러가 시험으로 LTE로 쉬게 했다(20:24:02). 사용자가 설정에서 LTE 우선을 눌렀다(20:24:49). 컨트롤러는 쉬는 시간이 끝나자 5G 우선으로 바꿨다(20:26:01). **사용자가 방금 고른 LTE를 5G로 덮어쓴 것이다.** 사용자의 원칙("사용자 설정이 우선, LTE를 고른 사람을 5G로 강제하지 않는다")에 어긋난다.
   - 원인: 컨트롤러는 "값이 바뀌었을 때"만 사용자 선택으로 봤다. 쉬는 중에는 이미 LTE라 사용자가 LTE를 눌러도 값이 그대로다. 폰은 이때도 알림을 보냈지만 컨트롤러가 무시했다.
   - 고친 뒤: 값이 그대로인 알림이라도 **컨트롤러 자신이 바꾼 지 10초 넘게 지나서 왔고**, 지금 값이 컨트롤러가 걸어 둔 LTE라면 "사용자가 LTE를 골랐다"로 본다. 그러면 원래 설정이 LTE가 되고, 컨트롤러는 손을 떼며 점도 사라진다.
     - 사용자의 선택은 밀려 있던 "쉬는 시간 끝, 5G 다시 시험"보다 먼저 적용한다(검증에서 찾은 빈틈: 둘이 거의 같은 순간에 오면 5G를 먼저 쓸 수 있었다).
     - 컨트롤러가 LTE로 바꾼 지 10초 안에 사용자가 같은 LTE를 누르면 여전히 놓친다(자기 알림과 구분하려는 여유).
     - 근거: 오늘 기록에서 컨트롤러 자신이 바꾼 뒤 오는 알림은 7번 모두 0.32초 안에 왔다. 사용자의 누름 알림은 47초 뒤에 왔다.
   - 상태: 폰에 설치함(20:51). PC 시험 통과. 검증 3회를 다 써서 마지막 수정(선택 먼저 적용·10초 여유·알림 시각)은 외부 검증을 받지 못했다.
   - **이 수정으로도 못 잡는 경우(20:54 폰 재시험에서 확인)**: 설정 화면이 이미 LTE로 맞게 보이는 상태에서 LTE 우선을 누르면, 삼성 설정이 "바뀐 게 없다"며 아무것도 하지 않는다. 폰이 알림을 보내지 않으니 컨트롤러도 알 수 없고, 2분 뒤 재시험이 5G 우선으로 바꿨다.
     - 이번 수정이 잡는 것은 화면이 예전 값(5G 우선)을 보이는 채 LTE를 누른 경우뿐이다(20:24 사례). 이 경우의 폰 재현은 아직이다.
     - 설정 화면만으로는 "쉬는 중인데 LTE로 계속 쓰겠다"를 전할 방법이 없다. 지금 쓸 수 있는 방법: 5G 우선을 눌렀다가 LTE 우선을 누른다(값이 바뀌므로 알아챈다). 또는 PC의 `nrctl keep-lte`.
     - 제대로 된 해법은 폰 알림에 "LTE로 계속" 버튼을 두는 것이다(설계에 이미 있는 계획, 동반 앱 기능 필요).

   - 5G가 풀린 155번 중 데이터를 쓰는 중이었던 것은 9번이었고, 2분에 3번을 넘은 적은 없었다.
   - 데이터 서비스 끊김은 모두 설정이 바뀐 직후(사용자가 고르거나, 시험 중 컨트롤러가 바꾼 직후 0.5초 안)의 재접속이었다. 이런 끊김은 세지 않는다.
7. 배터리 효과를 재지 않았다.
8. 5G 단독 망(SA)을 알아보지 못한다.
9. 듀얼 SIM이면 관찰만 한다.
10. 폰에서 재현하지 않고 PC 시험이나 코드 검토로만 확인한 비상 경로가 있다(DESIGN §5.11 "아직 확인하지 못한 것").
    - 예: 설정 바꾸기 실패와 되돌리기(롤백), 프로그램이 멈췄을 때 스스로 끝내기, 상단바 자리를 다른 것이 차지했을 때.
11. **설정 화면이 예전 값을 보여 줄 때가 있다**(09-28 저녁 폰 시험에서 발견). "설정 화면 = 실제" 원칙의 빈틈이다.
    - 있었던 일: 컨트롤러가 LTE로 바꾼 뒤(폰의 실제 값과 설정 저장값 모두 LTE), 사용자가 홈 버튼으로 나갔다가 설정을 다시 열자 네트워크 모드가 **5G 우선으로 보였다**. 두 번 모두 그랬다.
    - 뒤로 가기로 네트워크 모드 화면을 닫았다가 다시 열자 실제 값대로 보였다.
    - 해석: 설정 앱이 화면을 새로 만들 때만 저장값을 읽고, 홈 버튼으로 나갔다 돌아오면 전에 그려 둔 화면을 그대로 보여 주는 것으로 보인다. 09-27 시험(§2.8)은 화면을 다시 열어 확인했기 때문에 맞게 보였다.
    - 지금 할 수 있는 것: 설정을 볼 때는 뒤로 가기로 닫았다가 다시 연다.
    - 고칠 길: 컨트롤러가 바꾼 뒤 설정 앱이 화면을 새로 읽게 만드는 방법이 있는지 조사한다(§7).
12. 다시 시험한 뒤의 "데이터 사용 60초 쌓기" 판정이 영상 시청에서는 잘 채워지지 않는다(09-28 저녁 폰 시험).
    - 영상을 3분 넘게 틀었는데도 통과 판정이 나지 않은 채 화면이 꺼졌다.
    - 기록을 보면 영상 앱은 8초쯤마다 1~4초씩 몰아서 받고 쉬었다. 받는 동안과 3초 이하로 쉰 틈만 사용으로 쌓는데, 판정 구간 약 3분 26초 동안 쌓인 사용 시간은 약 41초였다(기준 60초).
    - 판정이 안 나도 5분(화면 켜진 시간)이 지나면 "판정 불가"로 평소 상태로 돌아가므로 해가 되지는 않는다. 다만 재시험이 실제로 통과·실패를 가리지 못하는 일이 잦을 수 있다. 실사용 기록을 보고 기준을 조정한다.
13. Wi-Fi 되돌리기는 "원래 설정으로 돌아가는 일"이라 시간당 횟수 제한을 받지 않는다.
    - 그래도 LTE로 내리는 쪽은 제한(한 시간 4번, 되돌리기 포함해서 셈)을 받는다.
    - 그래서 Wi-Fi를 자주 붙였다 떼어도 한 시간에 바뀌는 횟수는 많아야 5번 정도다.
14. **설정 바꾸기가 중간에 실패해 되돌려진 뒤(롤백)에는 관찰만 한다.** 이 상태에서 LTE로 쉬고 있었다면 Wi-Fi에 붙어도, PC에서 다시 켜기(resume)를 해도 5G로 되돌리지 않는다.
    - 풀리는 길: PC에서 끄기(stop)를 하면 되돌리기를 다시 시도한다. 사용자가 설정에서 모드를 고르면 그 모드는 반영되지만, 컨트롤러는 계속 관찰만 한다(자동 제어로 돌아오려면 PC에서 껐다 켜야 한다).
    - 폰에서 이 실패가 난 적은 아직 없다.

**이전 목록(09-28 기준)**
1. **설계 변경(DESIGN §5.12) 폰 설치·확인**: 구현·PC 시험 완료. 사용자 승인 뒤 설치하고 세 가지를 확인한다.
   - 쉬는 중 LTE 우선을 누르면 설정 값이 바뀌고 컨트롤러가 멈추는지 → 09-29 확인: 쉬는 중 화면이 이미 LTE로 보여 이 시험은 성립하지 않는다(위 09-29 결과)
   - 그때 상단바가 LTE로 보이는지
   - 쉬는 중 Wi-Fi에 붙으면 5G 우선으로 되돌리는지
   - 이전 설명: **사용자 설계 변경안(DESIGN §5.12): 설정에서 고른 5G 우선/LTE 우선을 고정값으로.** 컨트롤러는 설정 저장값을 건드리지 않고 실제 연결만 LTE로 쉬게 한다. 그래서 설정 화면은 계속 5G 우선으로 보이고, 상단바는 LTE, 점은 유지된다. 그러면 쉬는 중에도 설정 화면에는 5G 우선이 보이므로, 사용자가 LTE 우선을 누르는 것은 삼성 설정 입장에서 "변경"이 되고 설정 저장값이 바뀐다. 컨트롤러는 이 저장값 변화로 사용자 선택을 가리도록 설계를 바꾼다(§5 2번의 근본 해결). 이 조합에서 저장값이 실제로 바뀌는지와 알아채는 시점은 구현 뒤 폰에서 확인한다. 분석 결과 구현 가능하다. 구현 시점은 사용자 결정 대기.
2. 같은 자리에서 쉬는 중 Wi-Fi 되돌리기도 폰에서 확인한다(§5 1번의 🧪).
3. 설정 화면이 예전 값을 보여 주는 문제(§5 11번)를 조사한다: 설정 앱이 네트워크 모드를 어디서 읽고 언제 다시 읽는지(읽기 전용 분석부터).
4. 켜 둔 채 실사용을 계속한다. 지하철처럼 5G가 흔들리는 곳을 지나면 PC로 기록을 가져와 확인한다: 스스로 LTE로 내렸는지, 너무 자주 바꾸지는 않았는지, 재시험 판정이 나는지(§5 12번).
