## 0. 먼저 알아 둘 것: 지금은 "앱"이 아니다

지금 만들어진 것은 **PC로 폰에 설치해 켜는 개발용 시제품**이다. 앱 서랍에서 아이콘을 눌러 "시작"하는 앱은 아직 없다.

이렇게 된 이유는 권한 때문이다.
- 네트워크 모드(5G/LTE)를 바꾸는 권한은 구글이 일반 앱에 주지 않는다.
- 이 권한은 "디버깅" 통로로 얻는다. 개발자가 폰을 조작할 때 쓰는 통로로, USB 케이블 연결과 무선(Wi-Fi) 연결 두 가지가 있다.
- 지금 시제품은 PC가 USB 디버깅으로 폰 안에 작은 프로그램을 넣고 켠다. 무선 디버깅을 쓰면 PC 없이도 될 수 있으며, 그것이 §4의 방법 A·B다.
- 한 번 켜 두면 케이블을 뽑아도 폰 안에서 혼자 돈다. 재부팅하면 꺼진다.

다른 사용자가 앱처럼 설치해 쓰게 하려면 무엇이 더 필요한지는 §4에 적었다.

## 2. 지금 버전을 쓰는 방법 (PC가 있는 사람)

### 2.1 준비물 (한 번만)

1. **PC**(Windows 또는 Mac)에 두 가지를 설치한다.
   - 파이썬 3.8 이상
   - 안드로이드 `platform-tools`(adb). 구글이 무료로 배포한다.
2. **폰**에서 USB 디버깅을 켠다.
   - 설정 > 휴대전화 정보 > 소프트웨어 정보 > "빌드번호"를 7번 누른다 → 개발자 옵션이 생긴다.
   - 설정 > 개발자 옵션 > "USB 디버깅"을 켠다.
   - One UI 6 이상이면 "자동 차단"(Auto Blocker)을 꺼야 USB 명령이 된다.
3. **USB 케이블**로 PC와 폰을 연결한다. 폰에 "USB 디버깅 허용?"이 뜨면 허용한다.
4. **프로젝트 폴더**를 PC에 둔다.
   - 지금은 `nrd.dex`와 동반 앱을 PC에서 직접 빌드해야 한다(JDK 17 + 안드로이드 SDK 필요, `bash daemon/build.sh`, `bash app/build.sh`).
   - 다른 사용자에게 줄 때는 미리 빌드한 파일을 함께 줘야 한다(§4).

### 2.2 설치와 켜기

PC 명령창에서 프로젝트 폴더로 가서 실행한다.

```
python pc/nrctl.py doctor
python pc/nrctl.py install
python pc/nrctl.py start
```
- `doctor`: 폰이 연결됐는지, 쓸 수 있는지 점검한다(아무것도 바꾸지 않음).
- `install`: 동반 앱(작은 점)을 설치한다. 처음 한 번만.
- `start`: 컨트롤러를 폰에 넣고 켠다.

켠 뒤에는 케이블을 뽑아도 된다.

### 2.3 평소 사용 (폰만으로)

- **5G를 쓰고 싶으면** 폰 설정 > 연결 > 모바일 네트워크 > 네트워크 모드에서 **5G 우선**을 고른다. 컨트롤러가 작동하고 상단바에 작은 점이 뜬다.
  - 예: 지하철에서 5G가 자꾸 끊기면 컨트롤러가 실제 연결만 LTE로 쉬게 한다. 상단바는 LTE로 바뀌고 점은 그대로다. 5분쯤 뒤 5G를 다시 시험한다.
  - 쉬는 동안에는 설정 화면도 LTE 우선으로 보인다(삼성 화면이 실제를 보여 줌). 이때 LTE 우선을 눌러도 컨트롤러가 알아채지 못한다. LTE로 계속 쓰려면 5G 우선을 한 번 눌렀다가 LTE 우선을 누른다. 이 불편을 없애는 방법은 시험 중이다(STATUS.md).
- **LTE만 쓰고 싶으면** 같은 곳에서 **LTE 우선**을 고른다. 컨트롤러는 곧바로 손을 떼고, 폰은 순정 LTE 모드가 된다. 점도 사라진다.
- **Wi-Fi에 붙으면** 순정과 같다. 점이 사라지고, 쉬는 중이었으면 5G 우선으로 되돌린다.

### 2.4 끄기·확인·복구 (PC 필요)

```
python pc/nrctl.py status
python pc/nrctl.py stop
python pc/nrctl.py pull
python pc/nrctl.py report
python pc/nrctl.py restore
```
- `status`: 켜져 있는지, 지금 상태.
- `stop`: 끄기. 쉬는 중(LTE)이면 사용자가 고른 모드로 되돌리고 끈다. 끈 뒤 저장된 사용자 선택과 실제가 다르면 알려 준다.
- `pull`: 폰 기록을 PC로 가져온다.
- `report`: 가져온 기록을 요약한다(몇 번 LTE로 쉬었는지 등).
- `restore`: 긴급 복구. 컨트롤러가 꺼진 채 실제가 설정에 저장된 사용자 선택과 다를 때, 저장된 선택대로 맞춘다.

### 2.5 재부팅하면

컨트롤러가 꺼진다. PC에 다시 연결해 `python pc/nrctl.py start`를 한다.
- 쉬는 중에 재부팅됐으면 "설정은 5G 우선인데 실제는 LTE"로 남을 것으로 본다. 반대 조합의 재부팅 시험 결과로 추정한 것이고, 이 조합은 아직 직접 시험하지 않았다.
- 다시 켜면 설정에 저장된 사용자 선택(마지막으로 고른 모드)을 보고 스스로 맞춘다. 켜지 않고 맞추기만 하려면 `python pc/nrctl.py restore`를 쓴다.

## 3. 지금 버전의 한계 (사용자 입장)

- PC가 있어야 켜고 끌 수 있다. 재부팅할 때마다 PC가 필요하다.
- 폰에서 상태를 보거나 끄는 화면이 없다. 보이는 것은 작은 점뿐이다.
- 확인한 폰은 갤럭시 노트20 울트라(국내판, One UI 5) 한 대뿐이다.
- 실제 불안정한 곳에서 자동으로 쉬는 동작, 배터리 효과는 아직 확인 전이다(STATUS.md).

## 4. 다른 사용자가 "앱 설치 → 시작"으로 쓰려면

목표 모습: 사용자가 설치 파일(APK)을 받아 설치 → 앱을 열고 "시작"을 누름 → 끝. PC는 필요 없다.

막히는 곳은 §0의 권한 하나다. 풀 수 있는 방법은 아래 다섯 가지다. **09-29 밤 폰 시험으로 E가 가장 유력해졌다.**

**E. 통신사 권한 경로(PC로 한 번 설치, 이후 PC 불필요) — 폰 시험 통과, 제품 미구현.**
- 방법: 폰의 통신사 설정에 우리 앱의 서명 인증서를 시험용으로 덧붙여, 폰이 이 앱을 "통신사가 인정한 앱"으로 대하게 한다. SIM은 건드리지 않는다. 기존 목록은 그대로 두고 끝에 덧붙인다.
- 사용자가 할 일: 처음 한 번 PC에 폰을 연결하고 설치 프로그램을 실행한다. 그 뒤로는 재부팅해도 앱이 스스로 켜진다.
- 확인된 것(DESIGN §5.13 관문 1·2·3·5): PC 시험 명령을 받은 앱이 자기 자격으로 5G를 막고 풀기, 재부팅 뒤 PC 명령 없이 자격 유지와 자동 시작, 판단 재료 수신.
- 확인 중: 장시간 생존(관문 4).
- 한계: SIM·eSIM 교체, 공장 초기화, 전화 앱 데이터 삭제, 삼성 업데이트(OTA), 안드로이드 버전 변경이 있으면 자격이 풀릴 수 있다. 그때는 PC로 다시 설치한다.
- 앱은 오래 살아 있기 위해 상주 서비스로 돈다. 배터리 최적화에서 빼야 한다. 설치 프로그램이 해 준다.

**지금 폰에 남아 있는 시험 상태(레퍼런스 기기, 2026-10-03 갱신)와 되돌리는 법(PC, USB 디버깅)**
- 2026-10-03 정리: 옛 시험 앱 `nrc.poc`·`nrc.companion`을 `adb uninstall`로 지웠다. 지우기 전에 허용 타입 네 사유(USER·POWER·CARRIER·ENABLE_2G)를 읽어 모두 5G 포함임을 확인했다(남은 5G 막음 없음). `nrc.poc`의 배터리 최적화 제외 항목은 삭제와 함께 빠졌다. 제품 앱은 그대로(권한·배터리 최적화 제외·실행 유지, 사유 값·설정 화면 값 변화 없음).
- 제품 앱 `nrc.controller`(09-30 개발 시험용, 인정 목록 3번째 줄 `2186eadb…:nrc.controller`): `adb uninstall nrc.controller`. 목록에서 이 줄만 빼려면 `clear 2 true`로 비운 뒤 남길 줄을 `add 2 true <줄>`로 다시 넣는다.
- 인정 목록에 **`2186eadb…:nrc.poc` 줄은 남아 있다**(앱만 지움). 이 줄은 패키지 이름 `nrc.poc`와 개발 키 인증서가 **함께** 맞는 앱에만 권한을 준다.
  - **앱 삭제는 권한 회수가 아니다.** 이미 서명된 시험 APK(PC의 `poc/carrier/build/nrc-poc.apk`, 저장소 밖)를 다시 설치하면 개인키 없이도 등록 절차 없이 권한이 곧바로 다시 생긴다(09-29 23:19:35 재설치 실측, research §2.15).
  - 이번에 남긴 이유: 지금 있는 도구에는 줄 하나만 빼는 명령이 없다(`SetupTool`은 has/add, `CcTool`은 get/add/clear). 기존 명령으로 clear 후 재추가하면 그 사이 제품 앱 권한도 풀리므로 하지 않았다. 해당 줄만 뺀 목록을 한 번에 넘기는 선택 제거는 가능하지만(이 키의 배열은 통째로 바뀜), 별도 도구와 검증이 필요하다.
- 통신사 설정 덧붙임(영구) 전체 되돌리기: `adb shell 'CLASSPATH=/data/local/tmp/nrc/cctool.dex app_process /system/bin nrc.CcTool clear 2 true'`. 설치 전에는 다른 덧붙임이 없었으므로 이것으로 원래 목록 `[59DFFFDDCCC1929A5C089E53B05A27A42F6517B1]`으로 돌아간다(제품 앱 권한도 함께 풀림). `get 2`로 확인한다.
  - `cctool.dex`는 스크래치패드 도구다. 제품 설치 프로그램에 같은 기능을 넣을 예정이다.

| **A. 폰 스스로 무선 디버깅** (권장 후보) | 처음 한 번: 개발자 옵션에서 "무선 디버깅"을 켜고, 앱에 짝 코드(6자리)를 입력 | PC가 필요 없다. 다른 앱 없이 우리 앱 하나로 된다 | 무선 디버깅은 Wi-Fi에 연결돼 있어야 켜진다(시작할 때만 필요). 재부팅 뒤 자동으로 다시 켜기는 추가 권한으로 가능할 것으로 보이나 이 폰에서 확인해야 한다. 구현량이 크다(연결 절차를 앱에 넣어야 함) |
| **B. Shizuku 앱에 기대기** | Shizuku(무료 공개 앱)를 설치해 무선 디버깅으로 한 번 시작 → 우리 앱 허용 | 구현이 쉽다. 많은 사용자가 이미 쓰는 방식 | 앱이 두 개가 된다. 재부팅 뒤: 공식 Shizuku 13.6.0은 루팅 없이도 스스로 켜질 수 있다 — 조건은 안드로이드 13 이상, Shizuku 설정의 '부팅 시 시작' 켜짐, 그 Wi-Fi에서 무선 디버깅을 '이 네트워크에서 항상 허용'으로 허락함, 폰이 켜지는 그때 그 Wi-Fi에 연결돼 있음(Shizuku 13.6.0 소스 분석, 2026-10-04 — 이 폰 재부팅 시험 예정). 조건이 안 맞으면(예: Wi-Fi 없는 곳에서 재부팅) 사용자가 Wi-Fi에 붙은 뒤 Shizuku를 다시 시작해야 한다. 처음 결정(09-26)은 "Shizuku 없이 자체 방식"이었고, 지금은 등록 방식이 막힌 폰용 길 2로 제품 앱에 들어갔다(DESIGN §5.15) |
| **C. PC로 한 번 켜기 + 앱 화면** | 지금처럼 PC로 켜고, 폰 앱에서 상태 보기·끄기 | 지금 구조를 그대로 쓴다 | 재부팅마다 PC가 필요하다 → 일반 사용자용으로는 부족 |
| **D. 루팅 폰 전용** | 루팅(Magisk) 모듈 설치 | 재부팅해도 자동으로 켜지고 가장 단순하다 | 루팅한 사용자만 쓸 수 있다(소수) |

어느 방법이든 공통으로 더 만들어야 하는 것:
- 앱 화면: 시작/끄기 버튼, 지금 상태(5G/쉬는 중), 기록 요약
- 설치 파일(APK) 배포
  - 이런 권한을 쓰는 앱은 플레이스토어 심사가 까다로울 수 있다. 그래서 GitHub 같은 곳에서 직접 배포하는 것부터 생각한다.
- 여러 폰 지원(로드맵 B): 켤 때 그 폰에서 되는지 스스로 점검하고, 안 되면 이유를 알려 준다
- 사용 설명서(이 문서의 일반 사용자판)

진행 순서와 방법은 사용자가 정한다(STATUS.md §7).
